# LiquidVivo 管理网页

GitHub Pages 静态网页 + Supabase Auth / PostgreSQL。中性黑白灰、浅深色模式；无第三方字体请求，不使用大面积磨砂背景。

## 当前完成范围

- 登录、邮箱注册/确认、密码重置、自动登录选项、退出本机/全部会话。
- 管理员权限来自数据库白名单，不读取用户可编辑 metadata；管理数据及操作强制要求 TOTP 的 aal2 会话。
- 系统已有设备登记、短时一次性配对凭证、普通账号一对一绑定。仅输入设备码不能认领；设备持有者的核对及凭证交付需要管理员完成。
- 设备备注、搜索、筛选、排序、全选筛选结果、多选、反选、批量权益、撤销云端权益、独立黑名单和解除、解绑。
- 全员限免活动，指定设备/全部设备的弹窗、横幅、通知、日志及版本提示配置；停止活动/消息；操作记录。

当前版本是云端管理层，不是 Android 在线授权执行的完成版本。598 APK 不消费这些表；设备自动登记、认证心跳、签名策略发布、手机展示、回执以及一小时 Android 同步还没有接入。网页明确提示这一状态，不伪造设备/送达数据。云端撤销不会自动修改历史离线授权，在线协议接入必须保留固定身份和离线永久规则。

## 初始化（项目所有者执行一次）

1. Supabase 项目 → SQL Editor → New query，把 `supabase/001_console.sql` 完整复制进去并执行。它创建新的 lv_* 表和受权限保护的函数，不删除已有项目数据；不重复执行。
2. Authentication → URL Configuration，把 GitHub Pages 的完整网站地址配置为 Site URL，并加入 Redirect URLs；本地开发另加精确 `http://127.0.0.1:4176/`。不要使用任意域名通配符。
3. Authentication 的邮箱提供方保留邮箱确认，密码长度配置至少 12 位。先用站点注册你自己的管理员邮箱并确认邮件，不在聊天发送密码。
4. 执行 `supabase/002_promote_owner.sql`，它仅提升指定且已验证的所有者邮箱。不向匿名 API 暴露提升接口。
5. 重新登录网站，使用身份验证器设置 TOTP；管理员操作前必须完成二次验证。二维码包含 TOTP secret，只由所有者扫码，不能截图公开。
6. 对普通用户开放注册前配置自己的 SMTP，按实际域名设置发件与反滥用策略、邮件速率和 CAPTCHA。Supabase 内置测试邮件服务不能当作面向所有用户的正式邮件系统。CAPTCHA 接入还需站点 key；当前没有配置，不能声称已启用。

## 使用

管理员在设备页粘贴核实过的现有 LV2 设备码、填写名称，生成配对凭证；通过已核对的设备持有者渠道交付。普通用户验证邮箱后用设备码 + 凭证绑定；凭证 128 位随机、15 分钟有效、服务器只存 SHA-256、绑定原子消费，重发使旧凭证失效。解除绑定不改变设备码。一个账号一个设备，一个设备一个账号，数据库唯一约束防并发重复绑定。

无原始序列号上云；存储标识是 `SHA-256(UTF8("LiquidVivo/console/device/v1\n" + 原有设备码))`，这是在线索引算法，不修改 LV1/LV2 本身。配对不自动授予赞助。管理员笔记仅用于管理，当前数据行的 owner 也能读到自己的 note；不要在 note 写入不希望该用户看到的内容。

设置新的限时权益采用新增记录，永久记录不会被较短的记录覆盖；撤销操作仅撤销云端记录。活动使用起止时间，网页按浏览器时区输入，数据库保存 timestamptz。全员活动包含未来登记设备；消息的指定目标为发布时选中的明确设备 ID。账号列表不是在线/已读证明，last_seen 为空就显示尚未联系。

## 本地开发与发布

```
npm ci --ignore-scripts
npm run dev
npm run build
npm run preview -- --port 4176
```

代码应发布至独立 GitHub 仓库，不能把 Android 项目、私钥、台账、设备码名单或本机诊断上传到公开 Pages 仓库。`.github/workflows/pages.yml` 使用 GitHub Actions 发布 dist；仓库 Pages 的 Source 选择 GitHub Actions。只有 URL 与 Publishable key 位于网页中；不需要网页持有数据库密码、Secret key 或 GitHub 写令牌。

## 安全与验收边界

所有 lv_* 表启用 RLS，匿名无访问，authenticated 无直接写权限；关键 RPC 内部再次检查管理员白名单 + aal2。普通用户的 SELECT 通过 owner_id 约束，修改 JWT metadata 不能提权。配对失败使用统一错误。动态内容以文本转义，不执行远程 HTML/脚本，只允许 HTTPS 链接；CSP 限制脚本和网络目标。不保存密码，自选自动登录时由 Supabase SDK 持久保存会话令牌；浏览器密码管理器可另行保存密码，网页不读取它。

公开注册还需部署后的速率、CAPTCHA、邮箱投递和权限测试；本地语法/构建通过不等于生产安全验收。不要承诺绝对无漏洞。管理员凭证、配对凭证、会话令牌应视为敏感信息。浏览器本地会话仍受同源脚本与本机安全影响。

Supabase SQL 尚未由项目所有者执行时，RPC 返回 PGRST202，这是部署未完成，网页会显示初始化提示；不能通过放开 RLS 来规避。自动授权同步将另行采用有签名的版本化协议，不信任普通用户写入的“已授权”字段。
